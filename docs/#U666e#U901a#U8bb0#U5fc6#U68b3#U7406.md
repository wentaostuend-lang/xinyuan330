普通总结记忆仍使用原来的文字记录。长期记忆 → 原始记忆区域 →「记忆梳理」可查看当前概况、选择旧记忆、查看建议、设置读取方式和撤销操作。

默认开启历史时间与事件状态解释，新总结后自动梳理并应用有明确依据的结果。可在「设置」改为自动生成建议、手动应用，或关闭自动整理。结构化与向量模式的读取逻辑保持原状。

自动核对会从全部原始历史中挑选相关候选，默认最多20条；可调整数量，0表示不限相关候选。已存在的概况也参与核对。它不保证找全所有旧事件；大量旧数据可在「旧记忆」搜索并选择约定和结果，或通过「多角色」分别生成建议。

概况、历史与建议均可查看。建议支持逐项选择、编辑正文、状态、事件时间和来源后应用。自动状态变更需要可靠的用户原聊天引用或手动添加的原文依据；旧摘要单独不足以自动确认履行、取消或改期，不确定内容保留待核对。

读取方式可选择「概况 + 带关联说明的历史」「概况优先 + 未关联历史」「只读历史正文」。默认保留历史细节；概况优先会省略已关联的历史正文，可能减少摘要中其他细节。关闭解释并选择只读历史可恢复原来的读取方式。现有历史条数限制保留。

旧记录原文不被自动改写或删除。保存时间不被当成事件时间；原聊天无法可靠关联时不会编造日期。原记录编辑、删除、精炼替换后，依赖它的概况停止参与读取，可手动重新关联或重新梳理。梳理与精炼不会推进聊天总结进度。

每个角色设置与概况独立。每批字符预算可配置；超过预算明确停止，不悄悄截断。长记录分片，批次有检查点；可暂停、刷新后继续。调整预算需放弃旧任务再创建。接口失败不删除已保存的总结，可从未完成批次继续。

应用、手动编辑和移除概况均有操作记录。撤销只针对该操作，不删除后来新增的历史；相关概况后来发生变化时，需先撤销关联操作。未选择的建议可以继续应用，也可以结束草稿；结束不移除已应用结果。

记忆 JSON、可导入 TXT、角色记忆存档和记忆分类备份包含概况信息；阅读版 TXT 包含有效概况正文。旧格式数组仍可导入。替换旧格式时清除不匹配的旧概况、保留接收角色的梳理设置；合并时保留接收角色设置并核对来源。

梳理使用现有总结接口（有完整副接口配置时使用副接口），会消耗 API 额度。输入量与请求次数为估算，不显示未经接口价格确认的费用金额。正常聊天读取本地保存的概况，不为每条聊天额外发起整理请求。
